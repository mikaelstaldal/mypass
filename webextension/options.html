MyPass

Fill HTTP authentication dialogs

Answer a site's HTTP authentication challenge (the browser's own username/password dialog) from your vault, instead of showing the dialog.

This needs permission to see requests to all sites, which is why it is off by default. When it is on, MyPass answers a challenge only when:

  • it is a page you navigated to — never an image, script or frame;
  • the site is https: (or loopback), never a proxy;
  • the vault is unlocked, or you take up the offer to unlock: a locked vault holds the page load and the toolbar popup asks, so a page can put the offer up but only your click raises the passphrase prompt. Until the vault is open MyPass cannot tell whether it even has a login for the site, so that offer comes from any site that asks; one you dismiss is not asked about again for five minutes;
  • at least one entry matches the site and the realm it challenges for.

In every other case the browser's own dialog appears, as it does today.
